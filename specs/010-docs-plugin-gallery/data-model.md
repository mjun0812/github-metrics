# Data Model: Per-plugin docs with real examples

**Date**: 2026-05-19 | **Plan**: [plan.md](./plan.md) | **Research**: [research.md](./research.md)

The feature has no runtime data model — the change surface is
documentation artifacts (markdown + SVG) and one new generator
tool. Six "entities" are captured below to ground the contract docs.

## E-001: Plugin doc page (`docs/plugins/<slug>.md`)

- **One per adopted user-facing plugin** (19 total).
- **Hybrid structure** (per [research.md R-003](./research.md#r-003-plugin-doc-structure--auto-generate-vs-hand-write-vs-hybrid)):
  - **Auto-generated zones** bounded by `<!-- AUTOGEN_START: <name> -->`
    / `<!-- AUTOGEN_END: <name> -->` markers. Currently three:
    - `title-and-description` — H1 + 1-paragraph description sourced
      from `metadata.yml::description`
    - `config-table` — markdown table of every input the plugin
      accepts (columns: name / description / default / required / type)
    - `usage-snippet` — Action-mode YAML block enabling the plugin
      with a representative input set
  - **Human-authored zones** outside the markers: "When to use this
    plugin", "Common pitfalls", "Cross-references", and the
    sample-image embed (path is fixed; surrounding prose is per-plugin).
- **Generator**: `internal/tools/gen-plugin-docs` writes / refreshes
  the auto zones. Re-runs preserve human-authored zones byte-for-byte.
- **Discoverability**: every page is linked from README's plugin gallery
  (E-004).

**Spec linkage**: FR-003, FR-004, FR-007, FR-008.

## E-002: Sample SVG image (`docs/examples/plugin-<slug>.svg`)

- **Single-panel render** (per [research.md R-001](./research.md#r-001-sample-image-isolation--single-panel-vs-full-template-render)):
  the SVG embeds the rendered output of `metrics-cli --user
  mjun0812 --plugin_<slug> yes --output svg` with all OTHER plugin
  gates set to `no` (base + core always run).
- **Reproducibility**: dynamic strings (version footer + `Last
  updated` timestamp) are masked at write time via the M9
  `internal/testutil/golden/svg_normalize.go::NormalizeSVG`
  function. Committed bytes diff only on semantic change.
- **Sub-mode variants**: `plugin-languages-recent.svg` and
  `plugin-languages-indepth.svg` cover the two sub-modes of the
  `languages` plugin per Assumption.
- **File size**: typical 10-50 KB per plugin (varies with content
  density).
- **Generated by**: `scripts/gen-doc-samples.sh` invoked from
  `make docs-samples`.

**Spec linkage**: FR-004 (image embed), FR-005 (vendored),
FR-006 (regenerable), SC-003 (renders on github.com).

## E-003: Hero image (`docs/examples/hero-{classic,repository}.svg`)

- **Full-template render** (R-001 — all 19 adopted plugins enabled):
  - `hero-classic.svg` — `--template classic --user mjun0812`
  - `hero-repository.svg` — `--template repository --user mjun0812 --repo github-metrics`
- **Same normalization** as E-002 (NormalizeSVG mask).
- **Embedded near top of README.md** (FR-001), between AUTOGEN
  markers so the generator can refresh references on re-run.

**Spec linkage**: FR-001, SC-001.

## E-004: Plugins-gallery README section

- **Located in README.md** between `<!-- AUTOGEN_START:
  plugins-gallery -->` and `<!-- AUTOGEN_END: plugins-gallery -->`.
- **Content**: a 3-column markdown table (per
  [research.md R-004](./research.md#r-004-readme-plugin-gallery-layout--table-vs-list-vs-grid)).
  Each cell:
  - Thumbnail: SVG image link `[![<slug>](docs/examples/plugin-<slug>.svg)](docs/plugins/<slug>.md)`
  - Caption: backtick-wrapped slug linked to the doc page
- **19 plugins → 7 rows × 3 columns** (last row has 1 empty cell).
- **Generator**: same `gen-plugin-docs` tool writes this block
  (shares the metadata.yml read).

**Spec linkage**: FR-002, SC-002.

## E-005: Configuration table fragment (auto-generated inside E-001)

- **Source**: `assets/plugins/<slug>/metadata.yml::inputs`.
- **Output format**: markdown table with columns:
  - **Input** (input name, e.g. `plugin_languages_limit`)
  - **Description** (first line of the metadata.yml description)
  - **Default** (the `default:` value, or `—` if unset)
  - **Required** (`yes` / `no`)
  - **Type** (`boolean` / `string` / `number` / `array` per metadata.yml)
- **Invariant**: every input declared in metadata.yml MUST appear
  as a row in the table. Validated by the
  `gen-plugin-docs/main_test.go` test that counts metadata.yml
  inputs vs generated rows.

**Spec linkage**: FR-004 row 3, FR-007, SC-005.

## E-006: Generation invocation matrix

For each adopted plugin slug + each sub-mode variant, the
sample-generation script invokes:

```sh
metrics-cli \
  --user "${METRICS_DOC_USER:-mjun0812}" \
  --token-env GITHUB_TOKEN \
  --template classic \
  --output svg \
  --filename - \
  --plugin_${SLUG} yes \
  | go run ./internal/tools/normalize-svg-stream \
  > docs/examples/plugin-${SLUG}.svg
```

The full matrix is documented in
[`contracts/sample-generation.md`](./contracts/sample-generation.md) §2.

Hero invocations (E-003) enable the full plugin set for the
classic template and the repo-mode-capable subset for the
repository template (matching the M7 contract that limits
repo-mode to 7 plugins).

**Spec linkage**: FR-006, SC-004.
