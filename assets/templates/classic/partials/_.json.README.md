# `_.json` — classic partial dispatch order

This file enumerates the partials the classic template renders. The
github-metrics port keeps the file format byte-compatible with upstream
so the `sync-assets` workflow can refresh other classic assets without
clobbering this manifest.

## M2 scope

For M2, only four partials are wired (constitution principle III —
unadopted plugins MUST NOT appear in production paths):

- `base.header`
- `introduction` (stub; populated by M4 introduction plugin)
- `base.activity+community`
- `base.repositories`

## Upstream fallback

The full upstream listing (~46 entries) is preserved next to this file
as `_.json.upstream`. When a future milestone adopts a plugin, append
its partial name to `_.json` and add the implementation file under
`internal/templates/classic/partials/`. Do **not** simply rename
`_.json.upstream` back into place — the list must stay aligned with
adopted plugin code.
