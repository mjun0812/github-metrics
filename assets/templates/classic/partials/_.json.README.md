# `_.json` — classic partial dispatch order

This file enumerates the static partials the classic template renders
before iterating `PluginPartialOrder`. The github-metrics port keeps the
file format byte-compatible with upstream so the `sync-assets` workflow
can refresh other classic assets without clobbering this manifest.

## Current scope

Only one static partial remains:

- `introduction` (stub; populated by a future introduction plugin)

The legacy `base.header`, `base.activity+community`, and
`base.repositories` partials were dropped in #602:

- `base.header` was extracted into the `header` plugin
  (`internal/plugins/header/`). It now renders through
  `PluginPartialOrder` like every other plugin partial.
- `base.activity+community` and `base.repositories` were summary panels
  meant to fit inside a combined 1-SVG layout. With the per-plugin SVG
  embedding workflow they are dead weight — the standalone `activity` /
  `repositories` plugins already provide proper detail versions.

## Upstream fallback

The full upstream listing (~46 entries) is preserved next to this file
as `_.json.upstream`. When a future milestone adopts a plugin, append
its partial name to `_.json` and add the implementation file under
`internal/templates/classic/partials/`. Do **not** simply rename
`_.json.upstream` back into place — the list must stay aligned with
adopted plugin code.
