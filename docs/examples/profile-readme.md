# Profile README Example

This example shows how to compose a GitHub profile README from per-plugin SVG files
generated by github-metrics.

## Workflow Setup

```yaml
# .github/workflows/metrics.yml
name: Metrics
on:
  schedule:
    - cron: '0 */6 * * *'
  workflow_dispatch:

jobs:
  metrics:
    runs-on: ubuntu-latest
    permissions:
      contents: write
    steps:
      - uses: actions/checkout@v4
      - uses: mjun0812/github-metrics@v1
        with:
          user: ${{ github.actor }}
          token: ${{ secrets.GITHUB_TOKEN }}
          output_dir: ./metrics/
          # Per-plugin mode does not use the built-in committer; commit the
          # generated SVGs explicitly in the next step.
          output_action: none
          plugin_header: true
          plugin_languages: true
          plugin_stars: true
          plugin_activity: true
      - name: Commit generated SVGs
        uses: stefanzweifel/git-auto-commit-action@v5
        with:
          commit_message: 'chore: update profile metrics'
          file_pattern: 'metrics/*.svg'
```

## Embedding in README.md

After the workflow runs, embed the per-plugin SVGs in your profile README:

```markdown
<img src="metrics/header.svg" width="100%">

<img src="metrics/languages.svg" align="left" width="48%">
<img src="metrics/stars.svg" align="right" width="48%">

<br clear="both">

<img src="metrics/activity.svg" width="100%">
```

Each SVG is rendered independently from the same API fetch — disabling a plugin
(or removing its `<img>` tag) does not affect the others.

## Combined Mode

If you prefer a single SVG file (legacy behavior):

```yaml
- uses: mjun0812/github-metrics@v1
  with:
    user: ${{ github.actor }}
    token: ${{ secrets.GITHUB_TOKEN }}
    combined: 'yes'
    filename: github-metrics.svg
    plugin_header: true
    plugin_languages: true
```
